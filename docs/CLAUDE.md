# CLAUDE.md

## North star

The end goal of this repo is **Loci**, a spatial memory agent on a Jetson Orin Nano Super + RealSense D415.
The full spec is `docs/LOCI_SPEC.md` (original: `docs/Loci_Proposal.pdf`). Read it before any work here.

## Working rules

- **Do not write project code until the user explicitly says to start.** The user gives the first steps and requirements one at a time.
- Follow the 8-week plan and its gates in order (Gate 1 → 4). Don't skip ahead.
- Every layer has a primary choice and a fallback (see the tech-stack table). Pick the fallback only when the primary is shown not to work.
- Memory is the constraint: 8 GB shared CPU/GPU. One resident VLM only.
- Build from source for sm_87 on JetPack 7.2; don't trust JetPack 6 wheels or containers.
- Verify exact versions and specs before claiming compatibility. Say so when unsure.
- Git branches: the default branch is `main`. Every new feature gets its own branch named `js-<feature-name>` (lowercase, words joined by hyphens, e.g. `js-vlm-baseline`), created from `main` and merged back into `main` when the feature is done. Don't put feature work directly on `main`, and never use `claude/...` branch names. Keep large files out of git (see `.gitignore`: models, engines, datasets, runs, videos).
- Commits are authored as the user (`git config user.name "Jenil Shingala"`, `user.email 160362895+jshingala@users.noreply.github.com`, `commit.gpgsign false`), with no Claude co-author or session lines. History was rewritten to this on Oct 12, 2026 at the user's request.
- Lessons from the Parcel3D download mess (Oct 12, 2026) — follow these:
  - Before suggesting a "speed-up" trick, say upfront whether it will likely help and what can go wrong. If a task is bound by an outside limit (e.g. Zenodo ~0.8 MB/s => ~15 h), say so plainly instead of offering tweaks.
  - Never claim a process is running, stopped or protected without evidence (`pgrep -a`, `tmux ls`, file size growing). Ask for the output first.
  - Long jobs: start tmux and the job in ONE command, e.g. `tmux new -d -s NAME -c DIR 'cmd; bash'`; never have the user paste `tmux new` plus commands together (the extra lines run outside tmux or the session already exists).
  - Downloads: one plain `wget -c` (with `--tries=0 --retry-connrefused --waitretry=30 --read-timeout=60`). Don't use multi-connection aria2 on Zenodo (throttled per client, it got slower) or on the exFAT disk (zero-fills gaps, froze). Never mix downloaders on one file.
  - Give steps in the order they must run, and warn when order matters (e.g. delete before starting a download into the same folder).
